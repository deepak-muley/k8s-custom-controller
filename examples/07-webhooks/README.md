# Sample 07: Webhooks

This example demonstrates how to implement admission webhooks for Kubernetes Custom Resources. Webhooks provide a powerful way to validate, mutate, and enforce policies on resources before they are persisted to etcd.

## What This Example Demonstrates

This sample showcases:
- **Mutating Webhooks**: Automatically set default values using the `webhook.Defaulter` interface
- **Validating Webhooks**: Validate resources on CREATE, UPDATE, and DELETE operations using the `webhook.Validator` interface
- **Admission Warnings**: Return warnings to users without rejecting the request
- **Complex Validation Logic**: Registry whitelisting, security policy enforcement, and cross-field validation
- **Webhook Server Setup**: Configure webhook server with TLS certificates

## Features

### Defaulting Logic
The webhook automatically sets default values:
- Sets `replicas` to 1 if not specified
- Sets `port` to 8080 if not specified
- Adds `docker.io` registry prefix if image doesn't specify a registry

### Validation Rules
The webhook enforces several validation rules:
- **Image Registry**: Only allows images from trusted registries (docker.io, gcr.io, ghcr.io, quay.io, registry.k8s.io)
- **Image Tag**: Rejects images with `:latest` tag for production deployments
- **Tag Requirement**: Ensures all images have an explicit tag
- **Privileged Containers**: Requires special annotation for privileged mode and limits to 1 replica
- **Sensitive Data**: Prevents storing passwords/secrets in environment variables
- **Warnings**: Issues warnings for dangerous operations (scaling down >50%, image changes, enabling privileged mode)

## API Definition

```go
type ValidatedAppSpec struct {
    // Image is the container image to run (validated against allowed registries)
    Image string `json:"image"`

    // Replicas is the number of replicas (0-10, defaults to 1)
    Replicas *int32 `json:"replicas,omitempty"`

    // Port to expose (1-65535, defaults to 8080)
    Port *int32 `json:"port,omitempty"`

    // Environment variables (validated for sensitive data)
    Env map[string]string `json:"env,omitempty"`

    // AllowPrivileged requires special annotation
    AllowPrivileged bool `json:"allowPrivileged,omitempty"`
}
```

## Webhook Implementation

### Defaulter Interface
```go
func (r *ValidatedApp) Default() {
    // Set default replicas
    if r.Spec.Replicas == nil {
        defaultReplicas := int32(1)
        r.Spec.Replicas = &defaultReplicas
    }

    // Set default port
    if r.Spec.Port == nil {
        defaultPort := int32(8080)
        r.Spec.Port = &defaultPort
    }

    // Add registry prefix if missing
    if !strings.Contains(r.Spec.Image, "/") {
        r.Spec.Image = "docker.io/library/" + r.Spec.Image
    }
}
```

### Validator Interface
```go
func (r *ValidatedApp) ValidateCreate() (admission.Warnings, error) {
    var allErrs field.ErrorList

    // Validate image registry
    if err := r.validateImageRegistry(); err != nil {
        allErrs = append(allErrs, field.Invalid(
            field.NewPath("spec", "image"),
            r.Spec.Image,
            err.Error()))
    }

    // Validate no :latest tag
    if strings.HasSuffix(r.Spec.Image, ":latest") {
        allErrs = append(allErrs, field.Invalid(
            field.NewPath("spec", "image"),
            r.Spec.Image,
            "image tag 'latest' is not allowed"))
    }

    return nil, allErrs.ToAggregate()
}
```

## Running

### Prerequisites
1. A running Kubernetes cluster (kind, minikube, or real cluster)
2. kubectl configured to access the cluster
3. cert-manager installed (for webhook certificates)

### Install cert-manager
```bash
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml
```

### Generate Certificates
For development, you can use the controller's built-in certificate generation or manually create certificates:

```bash
# Using openssl
openssl genrsa -out ca.key 2048
openssl req -x509 -new -nodes -key ca.key -subj "/CN=webhook-ca" -days 365 -out ca.crt
openssl genrsa -out tls.key 2048
openssl req -new -key tls.key -subj "/CN=webhook-service.webhook-system.svc" -out tls.csr
openssl x509 -req -in tls.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out tls.crt -days 365

# Create secret
kubectl create namespace webhook-system
kubectl create secret tls webhook-server-cert \
  --cert=tls.crt --key=tls.key \
  -n webhook-system
```

### Deploy
```bash
# Install CRDs
kubectl apply -f config/crd/

# Deploy webhook server
kubectl apply -f config/webhook/manifests.yaml

# Wait for webhook to be ready
kubectl wait --for=condition=available --timeout=60s \
  deployment/webhook-controller-manager -n webhook-system
```

### Test
```bash
# Apply sample (should succeed with defaults)
kubectl apply -f config/samples/validatedapp_sample.yaml

# Try invalid image (should fail)
cat <<EOF | kubectl apply -f -

kind: ValidatedApp
metadata:
  name: invalid-app
spec:
  image: nginx:latest  # Will be rejected - :latest not allowed
EOF

# Try unknown registry (should fail)
cat <<EOF | kubectl apply -f -

kind: ValidatedApp

  name: unknown-registry
spec:
  image: private-registry.company.com/app:1.0  # Will be rejected

# Try privileged without annotation (should fail)
cat <<EOF | kubectl apply -f -

  name: privileged-app
```

## Key Concepts

### Webhook Types

1. **Mutating Webhooks**: Modify requests before they are persisted
   - Implement `webhook.Defaulter` interface
   - Use for setting defaults, injecting sidecars, etc.

2. **Validating Webhooks**: Validate requests before they are persisted
   - Implement `webhook.Validator` interface
   - Use for policy enforcement, validation rules, etc.

### Webhook Registration

Webhooks are registered using kubebuilder markers:
```go
// +kubebuilder:webhook:path=/mutate-webhooks-examples-k8s-io-v1alpha1-validatedapp,mutating=true,failurePolicy=fail,sideEffects=None,groups=webhooks.examples.k8s.io,resources=validatedapps,verbs=create;update,versions=v1alpha1,name=mvalidatedapp.kb.io,admissionReviewVersions=v1
```

### Certificate Management

Webhooks require TLS certificates. Options:
1. **cert-manager** (recommended): Automatically manages certificates
2. **Manual**: Generate and manage certificates manually
3. **Built-in**: Use controller-runtime's built-in certificate generation

### Failure Policies

- **Fail**: Reject requests if webhook is unavailable (safe, recommended)
- **Ignore**: Allow requests if webhook is unavailable (dangerous)

## Common Issues

### Webhook Timeouts
If webhooks timeout, check:
- Webhook server is running and healthy
- Network connectivity to webhook service
- Certificate is valid and trusted

### Certificate Issues
If you see certificate errors:
- Ensure certificates are valid and not expired
- Check that certificate CN matches service DNS name
- Verify caBundle in webhook configuration matches CA certificate

### Validation Not Working
If validation isn't enforced:
- Check webhook configuration is applied
- Verify webhook rules match the resource
- Check webhook server logs for errors
